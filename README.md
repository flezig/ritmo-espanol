# Ritmo Español

Интерактивный тренажёр испанского языка для русскоязычных учеников. Проект
объединяет последовательные уроки A1, словарь уровней A1–A2 и B1–B2, адаптивное интервальное
повторение, грамматику, диктанты, упражнения по песням и игровые режимы.

## Возможности

- 1596 слов в 37 русскоязычных темах с естественными примерами и полным переводом;
- раздельные фильтры A1–A2 и B1–B2 в словаре, Practice и диктанте;
- 5 подробных уроков по 50 заданий;
- грамматические разделы, построенные по хронологии учебника И. А. Дышлевой;
- адаптивное повторение узнавания, активного воспроизведения, артиклей и аудирования;
- Practice с ручным вводом, аудио, контекстом, исправлением ошибок и вариантами ответа;
- игры «Детектив по тексту» и Spanish Rush;
- музыкальные упражнения с короткими фрагментами YouTube;
- диктант по словам из пройденных уроков и Practice;
- регистрация, восстановление пароля, смена почты и пароля и синхронизация прогресса между устройствами;
- единый поиск по словам, переводам, правилам, урокам и песням (`⌘/Ctrl + K`);
- профиль, XP, серии, прогресс и 68 достижений с локальной офлайн-копией;
- отправка отмеченных примеров и упражнений автору сайта;
- защищённые кабинеты учителя и ученика: приглашения, задания, ответы, проверка и комментарии;
- журнал реальных клиентских ошибок JavaScript, синхронизации и аудио;
- экспорт и импорт резервной копии JSON;
- светлая и тёмная темы, адаптивная навигация для телефонов и планшетов.

## Технологии

- React 19;
- TypeScript;
- Vinext и Vite;

- Cloudflare Workers/Wrangler для production-preview;
- Supabase Auth и Postgres с Row Level Security для аккаунтов и прогресса;

## Локальный запуск

Для уже созданной копии на этом Mac откройте приложение **Терминал** и выполните:

После строки `Local:` откройте указанный адрес в браузере. Обычно это
`http://localhost:3000`. Окно Терминала должно оставаться открытым; остановить
сайт можно сочетанием `Control + C`.

Для новой копии репозитория:

Без переменных Supabase сайт продолжает работать в гостевом режиме и хранит
прогресс только в браузере.

## Настройка регистрации и облачного прогресса

1. Создайте проект в [Supabase](https://supabase.com/dashboard).
2. Откройте `SQL Editor`. Сначала целиком выполните
   `supabase/migrations/0001_user_progress.sql`, затем целиком
   `supabase/migrations/0002_safe_sync.sql`, затем
   `supabase/migrations/0003_client_errors.sql`, затем
   `supabase/migrations/0004_teacher_student.sql`. Первый файл создаёт таблицы и
   правила доступа, второй добавляет безопасную синхронизацию между несколькими
   устройствами и надёжную очередь жалоб, третий — защищённый журнал ошибок.
   Четвёртый создаёт роли, связи учитель–ученик, задания, проверки, комментарии,
   уведомления и строгие политики RLS.
3. В `Authentication → URL Configuration` укажите публичный адрес сайта как
   `Site URL` и добавьте этот же адрес в `Redirect URLs`. Для локальной проверки
   добавьте `http://localhost:3000`. Эти адреса используются также ссылками
   восстановления пароля и подтверждения новой почты, поэтому production-адрес
   должен быть внесён до проверки аккаунта на опубликованном сайте.
4. Скопируйте из `Project Settings → API` значения `Project URL` и публичный
   `anon`/`publishable key`.
5. Для локальной разработки создайте `.env.local` по образцу `.env.example`:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://ВАШ_ПРОЕКТ.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_ВАШ_КЛЮЧ
```

6. В настройках сборки Cloudflare добавьте эти же две переменные окружения и
   запустите новый deploy. Это публичные клиентские параметры; ключ
   `service_role` добавлять на сайт нельзя.

Если Cloudflare подключён к GitHub, опубликуйте готовые изменения из Терминала:

```bash
cd ~/Desktop/ritmo-espanol/ritmo-espanol
git add .
git commit -m "Add user accounts and cloud progress sync"
git push
```

Cloudflare автоматически начнёт новую сборку. После неё откройте сайт, создайте
тестовый аккаунт, подтвердите почту и войдите. Выполните одно упражнение, нажмите
«Сохранить сейчас», затем войдите в тот же аккаунт в приватном окне: результат
должен восстановиться. В Supabase откройте `Table Editor → user_progress`, чтобы
увидеть запись аккаунта.

Регистрация переносит текущий гостевой прогресс в новый пустой аккаунт. После
входа синхронизируются профиль, уроки, словарь, интервалы и точные даты SRS,
история слов, достижения, незавершённая Practice, диктантные источники, игровые
результаты, избранное, пользовательские слова и отметки контента. Голос озвучки
остаётся настройкой конкретного браузера, а добровольная аналитика остаётся
локальной. При одновременном изменении одних данных на двух устройствах сайт
не перезаписывает одну копию молча: он предлагает скачать обе и выбрать нужную.

Отмеченные пользователями задания доступны владельцу проекта в Supabase:
`Table Editor → content_reports`. Для очереди на проверку используйте фильтр
`status = pending`; после исправления можно вручную поставить `resolved`.

Ошибки авторизованных пользователей доступны в `Table Editor → client_errors`.
Поле `kind` различает `javascript`, `promise`, `sync` и `audio`. Журнал хранит
техническое сообщение, страницу и сведения браузера, но не ответы ученика.
Неотправленные события временно остаются в локальной очереди и повторно
отправляются после восстановления связи или следующего входа.

## Хранение данных и приватность

Без входа учебные данные сохраняются в `localStorage` текущего браузера. После
входа сайт оставляет локальную офлайн-копию и синхронизирует учебные данные с
записью пользователя в Supabase. При выходе локальная копия аккаунта очищается,
чтобы она не оставалась доступной следующему человеку на общем устройстве.

Схема хранения версирована. Выпущенные слова закреплены в
`app/lib/vocabulary-identities.ts`, а новые слова получают стабильный ID,
который не зависит от позиции в списке. Идентификаторы существующих уроков и
упражнений также нельзя переиспользовать: добавляйте новые записи с новыми ID.
Перед крупным изменением формата данных добавляйте последовательную миграцию в
`app/lib/storage-version.ts` и увеличивайте версию резервной копии. Старые
клиенты сохраняют неизвестные им поля облачного прогресса, поэтому выпуск нового
урока или типа данных не удаляет результаты пользователя.
Встроенные музыкальные задания обращаются к YouTube и зависят от его доступности
в регионе пользователя.

## Кабинеты учителя и ученика

После применения миграции `0004_teacher_student.sql` авторизованный пользователь
может открыть `/teacher` или `/student`. Учитель приглашает уже зарегистрированного
ученика по точному email. После принятия приглашения учитель создаёт задание на
странице ученика, а ученик отправляет ответ в `/student`. Все изменения статусов
выполняются SQL-функциями от имени текущего `auth.uid()`; передавать идентификатор
учителя или автора ответа из браузера нельзя.

Для ручной проверки используйте два аккаунта в разных браузерных профилях:

1. Откройте `/teacher`, отправьте приглашение на почту второго аккаунта.
2. Во втором аккаунте откройте `/student` и примите приглашение.
3. Учитель открывает ученика, назначает задание и срок.
4. Ученик отправляет ответ, учитель принимает его или возвращает на доработку.
5. Ученик видит оценку и комментарий на странице задания.
